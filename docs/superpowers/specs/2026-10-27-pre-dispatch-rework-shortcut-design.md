# 预派工正常模式返工快捷入口设计

## 背景

预派工页面的正常流程中，用户原本需要先手动把顶部类型切换为「返工」，再点击「添加产品」选择返工排产计划，才能进入返工派工。业务希望在正常模式下直接看到可返工提醒，并能一步进入对应返工预派工。

## 目标

在正常模式的两个位置提供「返工」快捷入口：

1. 「添加产品」弹窗中的左侧产品卡片。
2. 已添加产品点击后打开的右侧工序列表顶部栏。

入口只在存在可用返工排产计划时显示，不显示占位。

## 匹配与获取规则

正常模式按以下业务键匹配返工排产计划：

```text
生产编号 + 车间 + 排产类型 = 返工排产
```

查询时机固定为两处：

1. 点击正常产品并打开工序列表时，按该产品的生产编号查询。
2. 点击「添加产品」并打开产品弹窗时，按弹窗内正常产品集合的生产编号查询。

返工排产计划必须排除以下数据：

```text
返工进度 = 已完成
```

即已完成的返工排产计划不参与按钮显示和选择。

除上述条件外，查询口径与当前添加产品弹窗的可用数据口径保持一致，避免出现按钮可见但计划不可添加的情况。

## 点击流程

点击「返工」后：

1. 取该生产编号对应的可用返工排产计划。
2. 只有一条计划时，直接使用该计划进入下一步。
3. 多条计划时，弹出选择框。选择框展示：
   - 订单编号
   - 产品名称
   - 返工数量
   - 问题描述
   - 返工进度
   - 是否合并
4. 用户选择一条计划后，关闭添加产品弹窗或选择框。
5. 顶部类型自动切换为「返工」。
6. 使用选中返工排产计划 `rowid` 调用现有添加产品接口，生成返工预派工。
7. 添加成功后刷新返工产品列表，自动定位并选中对应产品，加载其返工工序列表。

处理过程中按钮进入加载状态，防止重复触发导致重复生成预派工。

## 模式切换与数据竞争处理

自动切换模式时按固定顺序处理，避免刷新和自动添加互相竞争：

1. 记录目标返工排产计划 `rowid` 与生产编号。
2. 将 `dispatchTypeFilter` 切换为「返工」。
3. 等待返工模式的数据刷新完成。
4. 调用预派工添加接口。
5. 添加完成后刷新产品列表并定位目标产品。

不修改排产计划、预派工和派工接口的数据结构。

## 错误处理

- 查询返工计划失败时不显示入口，并沿用页面现有错误提示方式。
- 自动添加失败时保留当前错误提示，不回切正常模式，方便用户重试或查看失败原因。
- 匹配结果为空时不显示入口。
- 多条计划未选择时不执行模式切换和自动添加。

## 测试方案

使用现有 Node 测试与 SFC 编译检查覆盖：

- 返工计划查询包含生产编号、车间、返工排产类型，并排除已完成返工进度。
- 工序列表打开时按单产品查询。
- 添加产品弹窗打开时按产品集合查询。
- 两个入口均只在正常模式且存在可用返工计划时显示。
- 一条计划直接进入流程。
- 多条计划弹出选择框，字段完整。
- 选择后使用正确 `rowid` 生成返工预派工。
- 添加完成后自动定位对应产品。
- 不影响现有正常/返工模式切换、添加产品、合并工序、使用正常工序和确认派工逻辑。

## 非目标

- 不新增返工排产计划与正常排产计划之间的关联字段。
- 不修改后端数据模型。
- 不改变返工派工现有业务流程。
