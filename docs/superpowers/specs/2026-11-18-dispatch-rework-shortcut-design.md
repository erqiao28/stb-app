# 派工页正常单据返工快捷入口设计

## 背景

预派工页已支持“正常模式下发现同生产编号的可用返工排产计划”快捷入口：点击「返工」后自动切换到返工模式；单条计划直接进入，多条计划先弹窗选择。正式派工页目前排产类型由选择订单/选择产品入口传入，正常单据卡片虽展示历史返工数量，但不能直接跳转到对应的返工排产单据。

## 目标

在正式派工页的正常单据卡片上提供与预派工页同口径的返工快捷入口，选中返工排产计划后自动加载该返工单据，并沿用正式派工页现有派工操作流程。

## 非目标

- 不改变正式派工接口、多对多派工逻辑、工序加载逻辑。
- 不自动提交派工；仍由用户使用现有“操作”“多对多派工”等按钮完成。
- 不做兼容或降级方案，不引入 mock 数据。
- 不修改订单派工/产品派工入口的原有筛选行为，除非快捷入口主动切换。

## 交互设计

1. 快捷按钮显示在正常单据卡片现有“返工数量”行的标签左侧。
2. 仅当前派工页列表为“正常排产”且该生产编号存在可用返工排产计划时显示。
3. 若历史 `reworkQty > 0`，继续按现状显示“返工数量”；若历史返工数量为 0 但存在可用返工排产，该行仍显示“返工数量：0”，用于承载左侧快捷按钮。
4. 查询或切换期间按钮显示“处理中”并禁止重复点击。
5. 单条可用计划：点击后直接进入该计划。
6. 多条可用计划：弹出“选择返工排产计划”，点击一条后进入。弹窗列与预派工页一致：订单编号、产品名称、返工数量、问题描述、返工进度、是否合并。
7. 选择后页面内切换 `billTypeFilter` 为“返工排产”，按选中计划的排产编号重新加载单据和工序，并定位该返工单据。
8. 切换后仍进入用户手动派工流程，不自动打开派工弹窗。

## 数据口径

可用返工排产计划查询口径与预派工页保持完全一致：

- 当前车间匹配。
- 生产编号匹配。
- 排产类型为“返工排产”。
- 排产状态为“已排产”或“部分排产”。
- 交货类型为“准时交货”。
- 满足现有添加产品范围筛选字段。
- “未完成工序数量 > 0”或“工序排产明细为空”。
- 返工进度排除“已完成”和“不可返工”。

多条计划按生产编号分组，必须人工选择一条，禁止自动全部添加或切换。

## 架构设计

- 新增共享工具模块，收敛排产计划字段 ID、可用返工计划查询、结果映射和“是否合并”格式化。
- 预派工页改为复用共享查询工具，删除页面内重复的查询映射实现。
- 派工页引入共享查询工具，在正常单据列表加载后按生产编号批量查询返工计划缓存。
- 派工页新增快捷入口状态：
  - 生产编号到可用返工计划列表的映射。
  - 多计划选择弹窗状态。
  - 当前处理中的生产编号。
  - 快捷切换目标排产编号。
- 切换时优先使用排产编号精确匹配目标返工单据，避免同生产编号多条计划混入或误选。

## 错误处理

- 返工计划提醒查询失败时提示“返工提醒加载失败”，但不阻塞正常单据列表和现有派工功能。
- 快捷计划缺少必要标识时不执行切换。
- 切换后未找到目标单据时保留返工模式列表并提示未找到目标返工单据，方便用户人工确认。
- 请求或加载失败会结束“处理中”状态，避免按钮永久禁用。

## 测试与验收

- 正常单据存在一条可用返工排产：按钮显示在“返工数量”左侧，点击后列表切为返工排产并定位目标单据。
- 正常单据存在多条可用返工排产：点击后先弹窗，点选一条后仅定位所选排产编号。
- 无可用返工排产：不显示按钮；原有 `reworkQty > 0` 的返工数量行仍正常显示。
- 返工排产列表：不显示快捷按钮。
- 预派工页原有返工快捷入口行为不变。
- 查询失败不影响正常列表加载。
- 人工检查代码中不新增 mock、假数据或重复字段口径。
